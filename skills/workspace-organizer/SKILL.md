# 工作区文件规范

本 skill 定义工作区里「文件放哪、叫什么、怎么改、怎么验」。目标不是一次性大扫除，而是让每次对话的文件操作都留下同样的结构，并且可回滚、可审计。

## 0. 自动触发

### 0.1 触发点

| 时机 | 判定 | 必须动作 |
|---|---|---|
| T0 任务受理 | 请求涉及创建、修改、移动、删除、导出、下载、整理、读取文件 | 先加载本 skill，再调用任何文件工具 |
| T1 首次写入前 | 即将创建或修改文件 | 运行 `preflight.ps1`，确认路径、命名、冲突 |
| T2 每次写入后 | 写完或移动完 | 微校验：存在、非空、路径正确、没有覆盖 |
| T3 任务收尾 | 准备给最终答复 | 运行 `audit.ps1`，修复违规后再汇报 |
| T4 发现根目录散落 | 与当前任务无关 | 只提示并给方案；用户确认后才批量整理 |

纯知识问答、不读写任何文件时，不加载本 skill，避免占用上下文。

### 0.2 常驻底线

工作区根目录的 `AGENTS.md` 保存本规范的 7 条底线，每次请求都会作为工作区指令注入。即使模型没有主动加载 skill，也必须遵守；加载 skill 是为了拿到完整步骤、脚本和修正规则。

skill 无法强制自我加载。要做到「不用每次下命令」，必须同时具备两层：

1. **常驻层**：根目录 `AGENTS.md` 的短规则，始终在上下文中。
2. **详细层**：本 skill，提供流程、脚本、校验和修正表。

### 0.3 用户覆盖

用户明确说「保持原样」「不要整理」「就放这里」时，以用户指令为准，并在答复中说明未按默认规范执行。

## 1. 目录与命名规范

### 1.1 分区

```
<工作区根>/
├─ 01_<主题>/ … 89_<主题>/
│  ├─ _输入/          用户提供的原始文件，归档后只读
│  ├─ _产出/          交付物，按日期与版本命名
│  └─ _归档/          被替代的旧版本、过期草稿
├─ 99_临时与杂项/
│  ├─ tmp/            中间文件，按任务分子目录
│  ├─ 未分类/         暂时判断不了主题的文件
│  ├─ 重复文件/       哈希确认后的重复副本
│  ├─ 归档/           用户要求删除但需保留的文件
│  └─ 整理记录/       迁移清单、回滚脚本、审计结果
├─ 整理说明.md        仅批量整理时生成
└─ 受保护目录         .git/.dsh/node_modules 等，不进入、不整理
```

- **主题区**：`NN_<主题>`，NN 取 01–89，长期存在。不要用日期做主题目录名。
- **角色区**：`_输入`、`_产出`、`_归档` 按需创建，不预建空目录。
- **临时区**：只放当前任务的中间文件，任务结束清理。
- **根目录只允许**：`NN_*`、`99_*`、受保护目录，以及 `README.md`、`AGENTS.md`、`CLAUDE.md`、`整理说明.md`。

### 1.2 文件角色

| 角色 | 存放位置 | 命名 | 生命周期 |
|---|---|---|---|
| 用户输入 | `<主题>/_输入/` | 保留原名 | 只读，任务结束保留 |
| 交付物 | `<主题>/_产出/` | `YYYY-MM-DD_<主题>_<描述>_v<N>.<ext>` | 长期保留 |
| 中间文件 | `99_临时与杂项/tmp/<task-id>/` | 自定义，稳定即可 | 任务结束删除或归档 |
| 旧版本 | `<主题>/_归档/` | `<原名>_归档<YYYY-MM-DD>` | 保留，不删除 |
| 重复文件 | `99_临时与杂项/重复文件/` | 保留原名 | 保留，不删除 |
| 迁移记录 | `99_临时与杂项/整理记录/run-…/` | 固定文件名 | 保留 |

### 1.3 命名规则

- **主题目录**：`01_考研`、`02_脚本工具`；中文主题直接写，不加日期。
- **交付物**：`2026-11-04_408_考点分析_v1.xlsx`。日期用生成日，描述 2–20 字，版本从 `v1` 起。
- **输入文件**：保留原名。同名不同内容加 `_v2`、`_2026-11-04`，不覆盖、不改原文件。
- **归档**：`原名_归档2026-11-04.ext`。
- **临时文件**：`20261104-整理工作区/step1.json`。
- **代码/项目**：遵循项目自身的 `snake_case`、`kebab-case` 或框架约定，不加日期前缀；只有交付物才用日期版本。
- **禁止名**：`新建文件夹`、`未命名`、`test`、`temp`、`copy`、`final`、`最终版`、`(1)`；Windows 保留名 `CON/PRN/AUX/NUL/COM1…`；结尾空格或点；`<>:"/\|?*`。

### 1.4 例外

- 项目自带布局（`src/`、`dist/`、`docs/`）优先，不强行套 `_产出`。
- 大型素材目录（`assets/`、`textures/`）整体归入主题，不逐个改名。
- 版本库、依赖目录、构建产物不整理、不审计。

## 2. 执行步骤

### 2.1 受理与定位

1. 列出请求涉及的文件和动作：读、写、改、移动、删除、导出、整理。
2. 找主题：按文件名、内容关键词、项目结构匹配现有 `NN_*`。
   - 唯一匹配 → 使用。
   - 多个匹配 → 用 `ask_user_question` 问。
   - 没有匹配 → 放 `99_临时与杂项/未分类/`，不要为一个文件新建永久主题；任务结束再建议主题。
3. 找规范路径：`_输入` → 主题根 → 工作区根。多个同名时用哈希和修改时间确认。
4. 只读请求：直接读，不复制、不移动。

### 2.2 接收输入

1. **工作区外的文件**：复制到 `<主题>/_输入/`，保留原文件；复制后校验大小和 SHA256。
2. **工作区内的散落输入**：移动到 `_输入/`；如果它是项目工作文件，留在项目目录。
3. **附件、下载**：先落到 `99_临时与杂项/tmp/<task-id>/`，校验后再归档到 `_输入/`。
4. **重名**：内容相同则复用；内容不同则加 `_v2` 或日期后缀，绝不覆盖。
5. `_输入/` 内的文件此后视为只读，不再修改；需要加工时复制到 `_产出/` 或 `tmp/`。

### 2.3 写入前预检

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<skill>\scripts\preflight.ps1" `
  -Root "<工作区>" -Target "<相对路径>" -Kind output `
  -OutputDirName '_产出' -InputDirName '_输入' -ArchiveDirName '_归档'
```

读取 JSON：

- `ok=true` 且 `action=create` → 按 `suggested` 写入。
- `action=reuse` → 已有相同内容，直接复用，不重复写。
- `action=version` → 用 `suggested` 的版本路径作为目标。
- `action=blocked` → 修正路径或询问用户，不能强写。
- `warnings` 中的 `role-dir`：确认是否项目自身布局；是则保留，否则移到角色目录。

预检会检查：是否越界、是否进入受保护目录、目标是否为目录、是否是 Windows 保留名、输出命名是否合规、是否已存在、父目录是否存在。传入 `-Source` 时会用 SHA256 判断是否可复用。

### 2.4 写入与生成

1. 先建父目录，再写文件。
2. 大文件、二进制、导出物：先写 `tmp/`，校验大小/哈希/可打开后再移动到最终路径。
3. 文本：写完后读回，确认非空、编码正确、关键内容存在。
4. 不写 `_输入/`；不在根目录产生新文件。
5. 同一批多个文件使用同一套命名，避免中途改名。
6. 生成的文件如果是临时的，明确放到 `tmp/<task-id>/`，不要混进 `_产出/`。

### 2.5 归档与清理

1. 被替代的旧版本 → `_归档/`，不删除。
2. 中间产物 → `tmp/<task-id>/`；任务结束删除自己创建的临时文件，或归档。
3. 重复文件 → 哈希确认后放 `99_临时与杂项/重复文件/`。
4. 用户文件永不删除。用户要求删除时 → 移到 `99_临时与杂项/归档/待删除/`，并二次确认。
5. 只有批量整理才更新根目录 `整理说明.md`；普通任务不写。

### 2.6 自检

按第 4 节执行 `audit.ps1` 和人工清单。未通过不得汇报完成。

### 2.7 汇报

- 列出新增、修改、移动的文件路径。
- 给出 audit 结果（`ok=true` 或剩余违规及原因）。
- 说明例外、被占用文件、未处理项。
- 小任务不用贴整棵目录树；大批量整理才给结构树和清单链接。

## 3. 约束条件

1. **不覆盖**：目标已存在时，同内容复用，不同内容用版本号或归档，绝不覆盖。
2. **不删除用户文件**：删除请求先归档并确认；只能删除自己创建且记录在案的临时文件。
3. **受保护目录**：`.git`、`.svn`、`.hg`、`.dsh`、`.dsh-im`、`.agents`、`.acl-recovery`、`node_modules`、`.venv`、`__pycache__`、`.npm-cache`、`dist`、`build` 不进入、不整理、不审计。
4. **不跨根**：所有源和目标都在当前工作区根目录内；外部文件只复制进来，不移动原文件。
5. **输入只读**：`_输入/` 中的文件不再修改；加工产物放 `_产出/` 或 `tmp/`。
6. **不擅自批量改名/移动**：一次移动多个顶层条目、重命名现有目录、合并文件夹，必须先出方案并得到用户确认。
7. **不批量改写内容**：不要用 `Get-Content`/`Set-Content` 批量重写脚本；GBK/UTF-8 混杂会损坏文件。
8. **原子写入**：大文件、二进制、导出物先写临时文件，校验后再移动到位。
9. **符号链接**：不跟随指向工作区外的 junction/symlink；移动前检查 `LinkType`。
10. **冲突停下**：目标已存在、被占用、权限不足、来源不明时停下询问，不猜测、不强行合并。
11. **根目录卫生**：根目录只允许分类目录、受保护目录和允许的说明文件。
12. **权限**：工作区外写入、移动中完整性文件、结束进程等操作需要用户批准，先说明原因再请求。

## 4. 自检要求

### 4.1 自动审计

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<skill>\scripts\audit.ps1" `
  -Root "<工作区>" `
  -OutputDirName '_产出' -InputDirName '_输入' -ArchiveDirName '_归档' `
  -RootAllow 'README.md','AGENTS.md','CLAUDE.md','整理说明.md'
```

审计范围：

- 根目录散落文件（`root-file`）。
- 顶层目录是否按 `NN_`/`99_` 编号（`top-dir-name`）。
- `_产出` 下的文件命名（`output-name`）。
- 临时/系统垃圾文件（`stray-temp`）。
- 空目录（`empty-dir`）。
- 超过 7 天的临时文件（`stale-tmp`）。

`ok=false` 时不得汇报完成。只读审计使用 `-Path` 限定子树，避免扫描整个工作区。

### 4.2 人工清单

| 检查项 | 合格标准 | 不合格处理 |
|---|---|---|
| 输入位置 | 原始文件在 `_输入/`，未被修改 | 复制回 `_输入/`，从备份恢复原文件 |
| 产出位置 | 交付物在 `_产出/`，不在根目录或 `_输入/` | 移到 `_产出/`，按规则重命名 |
| 产出命名 | `YYYY-MM-DD_主题_描述_vN.ext` | 用 `preflight` 的 `suggested` 重命名 |
| 版本 | 同名不同内容递增版本，不覆盖 | 从 `_归档/备份` 恢复被覆盖文件，重新版本化 |
| 临时文件 | `tmp/` 内，任务结束已清理 | 删除自己创建的，或归档 |
| 空目录 | 没有非角色区的空目录 | agent 创建的可删；用户的归档 |
| 重复文件 | 哈希确认，归档不删除 | 移到 `99_临时与杂项/重复文件/` |
| 根目录 | 只有分类目录和允许的说明文件 | 移入主题或 `99_临时与杂项/未分类/` |
| 脚本路径 | 移动后列出受影响的绝对路径 | 报告给用户，不擅自批量改写 |
| 例外 | 已记录并获得用户同意 | 补说明或回滚 |

### 4.3 违规修正

| 违规码 | 修正动作 |
|---|---|
| `root-file` | 移入对应主题的 `_输入/` 或 `_产出/`；无主题则 `99_临时与杂项/未分类/` |
| `top-dir-name` | 改名为 `NN_原名`，或并入已有主题；先确认不是版本库/项目根 |
| `output-name` | 用 `preflight.ps1` 生成合规名，重命名并记录 |
| `stray-temp` | agent 创建的删除；用户的移到 `_归档/` |
| `empty-dir` | agent 创建的直接删除；用户的保留或归档 |
| `stale-tmp` | 清理或归档到 `99_临时与杂项/归档/` |
| `protected-dir` | 立即停止，改到主题区 |
| `outside-root` | 移回工作区内，或改为复制 |

### 4.4 修正循环

1. 读 audit 的 `violations`。
2. 按 4.3 逐条修正；每步用 `preflight` 或移动记录留痕。
3. 重新运行 audit。
4. 直到 `ok=true`；剩余项必须是「用户资产、项目自身布局、已获同意的例外」，并在答复中逐条说明。
5. 不允许修改 audit 规则、放宽正则、隐藏违规来「通过」自检。

## 5. 批量整理

只在用户明确要求整理，或确认了方案后执行：

1. `inventory.ps1` 生成快照。
2. 输出 2–3 层分类树和移动数量，用 `ask_user_question` 确认。
3. 写 `plan.json`，逐条 `from → to`。
4. `organize.ps1 -DryRun` 检查 conflict/missing/already。
5. `organize.ps1` 执行，生成 manifest/rollback/summary。
6. `verify.ps1` 校验目标存在、源消失、无 `x\x` 嵌套。
7. 写根目录 `整理说明.md`，报告结构和回滚方式。

分类细节见 `references/classification.md`；Windows 权限、占用、嵌套、编码问题见 `references/windows-pitfalls.md`。

## 6. 特殊场景

- **用户说保持原样**：不整理、不改名，只完成请求本身。
- **项目仓库**：遵循项目现有布局；不把 `src/` 拆进 `_产出`。
- **只读文件/被占用**：先查占用进程，请用户关闭；不要结束进程。
- **外部绝对路径**：复制进 `_输入/`，保留外部原文件。
- **大文件**：先写 `tmp/`，校验后移动；避免一次性读入内存。
- **多主题**：按主要用途归一个主题，其余在说明中标注，不复制多份。
- **生成脚本**：项目脚本放项目目录并遵循项目命名；一次性脚本放 `tmp/<task-id>/`。

## 7. 反模式

- 把文件直接丢在根目录，或新建 `新建文件夹`。
- 用日期做主题目录名，导致目录爆炸。
- 同名文件直接覆盖，或用 `_final`、`_最终版` 代替版本号。
- 为了「整洁」删除重复文件或旧版本。
- 修改 `_输入/` 里的原文件，导致无法追溯。
- 任务进行中顺手大改目录结构。
- 只按扩展名分类，拆散项目。
- 审计失败后改规则，而不是改文件。
