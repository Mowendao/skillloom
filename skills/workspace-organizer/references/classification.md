# 分类参考

## 判断顺序

1. **先看项目边界**：目录里是否有 `package.json`、`pyproject.toml`、`.git`、`*.sln`、`Cargo.toml`、`go.mod`、`README`。有就是一个项目，整体移动。
2. **再看主题**：文件属于学习、工作、素材、逆向、课件、个人文档中的哪一类。
3. **最后看类型**：只有当同类文件确实互不相关（例如几十个独立安装包、零散截图）时，才按扩展名分组。
4. **不确定的放 `99_临时与杂项`**，并在说明里标注，后续再细分。

## 顶层模板

按实际内容取舍，不要为了凑数建空目录：

| 目录 | 放什么 |
|---|---|
| `01_学习资料` | 考试大纲、真题、笔记、课表、教材、复习计划 |
| `02_项目` | 有代码/构建文件的项目，按项目名分子目录 |
| `03_素材与美术` | 图片、参考图、工作流、教程、字体、音效 |
| `04_文档与报告` | 报告、方案、合同、演示文稿、导出 PDF |
| `05_工具与环境` | 可复用的脚本、依赖库、安装包、配置模板 |
| `99_临时与杂项` | 缓存、下载残留、重复文件、待分类、实验产物 |

领域明确时用领域名替代泛化名，例如 `01_考研`、`02_galgame逆向`、`03_ASMR日语`。

## 常见聚类信号

- **同一前缀/缩写**：`gxu2026.pdf`、`gxu2027.txt`、`gxu\` 属于同一所学校。
- **脚本与数据互引**：脚本里 `open("xxx.pdf")`、`fetch(...).save("yyy")`，说明它们是一个工作流，放一起。
- **时间聚集**：同一分钟/同一天生成的一批文件，通常来自同一次抓取或导出。
- **目录名与散落文件同名**：优先合并进已有目录，而不是新建平行目录。
- **空目录**：保留原位或归入 `99`，不要因为空就删除（可能是占位或待生成）。
- **图片序列**：`p001.png…p200.png`、`page-0001.png` 通常是某次渲染/切图，跟它的源文件和脚本放一起。

## 命名与编号

- 顶层用两位编号：`01_`、`02_`……`99_`，控制显示顺序。
- 目录名用中文主题或稳定的英文项目名；避免空格结尾、Windows 保留名（`CON`、`PRN`、`AUX`、`NUL`、`COM1`…）。
- 子目录可以保留原来的英文/拼音名，减少迁移成本。
- 迁移记录中的路径保持原样，便于回滚。

## 冲突与重复

- **同名同内容**：SHA256 相同 → 保留一份，另一份归档到 `99_临时与杂项\重复文件\`，不要删除。
- **同名不同内容**：不要覆盖。用 `_原始`、`_旧版`、`_v2`、日期后缀区分，并在说明里写清差异。
- **目标目录已存在同名文件**：先在计划阶段改目标名；`organize.ps1` 不会自动合并或覆盖。
- **目录合并**：不要直接 `Move-Item dir existing-dir`（会变成嵌套）。要合并时逐个子项移动，或先移走旧目录再放新目录。

## 不该动的东西

- `.git`、`.svn`、`.hg`：版本库。
- `.dsh`、`.agents`、`.claude`、`.cursor`：工具配置和 skill 根目录。
- `.acl-recovery`、`.system`：沙箱/系统恢复目录。
- `node_modules`、`.venv`、`venv`、`__pycache__`、`.next`、`dist`、`build`：可再生依赖/产物；可以整体归入项目的 `99` 子目录，但不要拆开。
- 正在运行的程序目录、数据库文件、虚拟机磁盘。

## 根目录收尾标准

- 只剩顶层分类目录、系统隐藏目录、一份 `整理说明.md`。
- 每个顶层目录都有明确用途，没有 `新建文件夹`、`未命名`、`其他` 这类占位名。
- `99_临时与杂项` 里的内容有归类说明，且不与正式资料混放。
- 迁移清单中的每个目标都存在，源路径都已消失。
- 没有 `x\x` 嵌套目录。

## 抽象示例

整理前：

```
root\
  a2026.pdf  a2026.txt  a2027.pdf  a2027.txt  a\  (已有目录)
  b2027.pdf  b_notes.txt
  build_a.py  fetch.py  scrape.js
  report.docx  report.md
  cache\  tmp\  old.zip
```

整理后：

```
root\
  01_资料\
    a\            (散落文件并入已有目录)
    b\
    build_a.py
  02_脚本\
    fetch.py  scrape.js
  03_文档\
    report.docx  report.md
  99_临时与杂项\
    cache\  tmp\  old.zip
  整理说明.md
```

要点：同项目的脚本和输出放在同一父目录；已有目录优先合并；临时物统一收进 `99`。

## 三区模型

每个主题区内部按角色分三层，按需创建：

```
01_<主题>/
├─ _输入/     用户提供的原始文件；归档后只读
├─ _产出/     交付物；YYYY-MM-DD_<主题>_<描述>_v<N>.<ext>
└─ _归档/     被替代的旧版本、过期草稿；<原名>_归档<YYYY-MM-DD>
```

判断规则：

- 用户给的、下载的、导出的原始材料 → `_输入/`。
- 自己生成、要交给用户的结果 → `_产出/`。
- 新版本替代旧版本 → 旧文件进 `_归档/`，不删除。
- 加工过程中的中间文件 → `99_临时与杂项/tmp/<task-id>/`，不要放 `_产出/`。

现有主题如果已经有自己的布局（例如 `01_考研/408真题与考点/`），不要为了套三区而拆散它；只在该主题的散落文件和新建交付物上使用 `_输入`/`_产出`/`_归档`。

## 命名速查

| 对象 | 规则 | 示例 |
|---|---|---|
| 主题目录 | `NN_中文主题` | `01_考研`、`02_脚本工具` |
| 交付物 | `YYYY-MM-DD_主题_描述_vN.ext` | `2026-11-04_408_考点分析_v1.xlsx` |
| 输入 | 保留原名 | `gxu2026.pdf` |
| 输入重名 | `_v2` 或 `_日期` | `gxu2026_v2.pdf` |
| 归档 | `原名_归档YYYY-MM-DD.ext` | `报告_归档2026-11-04.docx` |
| 临时目录 | `YYYYMMDD-任务slug` | `20261104-整理工作区` |
| 代码/项目 | 遵循项目约定，无日期前缀 | `build_xlsx.py` |

描述控制在 2–20 字，能区分同一主题下的不同产物；不要用 `final`、`最终版`、`新建`、`副本`。
