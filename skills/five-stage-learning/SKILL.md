# 五阶段学习（斯科特·杨）

带用户按「获取 → 理解 → 扩展 → 应用 ↔ 纠错」学一个具体知识点。**每次只推进一个阶段**，用出口条件判断能不能进下一阶段，不用时间判断。

## 阶段地图

```
获取 → 理解 → 扩展 → 应用
                      ↓ 失败
                    纠错 ──→ 回「理解」或「扩展」
```

- 主线：1→2→3→4；纠错是回边，只在第 4 步失败时进入。
- **最短闭环 = 1→2→4**（小知识点可跳过扩展）。
- **没有第 4 步的产出，不算学完。**

## 先判断知识类型

不同知识的验证方式不一样，别用错尺子：

| 类型 | 判据 | 主要验证方式 |
|---|---|---|
| **概念型** | 问"为什么成立 / 边界在哪" | 费曼讲解（第 2、4 阶段） |
| **程序型** | 问"能不能按步骤做对" | 闭卷做题 / 写代码（第 4 阶段） |
| **判断型** | 问"该不该 / 选哪个" | 写决策理由，让反对者来驳（第 4 阶段） |

## 第 1 阶段：获取

**目标**：拿到「最小可理解单元」，不是收藏资料。

**步骤**
1. 先用一句话写下这次要解决的问题。
2. 只取能回答这个问题的材料，上限 3 个来源或 1 章。
3. 记下来源、版本、以及"为什么选它"。
4. 读到自己能动手为止就停，**不做摘要**。

**在 DSH 里这样说**
- 「帮我用 3 句话划出 X 的边界：解决什么问题，不解决什么问题。」
- 「我要回答『Y』，这几份材料里哪份最合适？只给理由，不要总结内容。」
- 「我只有 40 分钟，给一条最小阅读路径（章节＋页数），不要知识清单。」

**出口**：能用一句话说清"这块要解决什么问题"，且手上有一份能动手的材料。
**失败信号**：开始搜第四份资料，或开始抄笔记 → 砍范围，退回第 1 步。

## 第 2 阶段：理解

**目标**：把外部表述转成你自己的表述（能复述，不是能认读）。

**步骤**
1. 合上材料，用自己的话写 3–5 句。
2. 找一个类比，只准一个。
3. 标出"我还没想通的那一句"。
4. **概念型知识加一步：费曼测试**——不看笔记讲 60 秒，禁用行话。

**在 DSH 里这样说**
- 「这是我的复述，只挑错和含糊的地方，不要重写我的句子。」
- 「用一个类比解释 X，然后指出这个类比在哪儿会失效。」
- 「我这句话里哪个词是含混的？逼我给定义。」
- 「你现在是外行，听我讲 60 秒，然后只做一件事：指出你哪个地方没听懂。」

**出口**：复述无硬错、类比能自洽、剩余含糊点 ≤1。
**概念型额外出口**：费曼讲解中每用一次行话记 1 次失败，**超过 2 次就不算过**，回去重讲（不是回去多读）。
**失败信号**：复述仍是原文句式 → 关掉材料重写。

## 第 3 阶段：扩展

**目标**：把知识接到你已有的结构上——纵向问因，横向找同构。

**步骤**
1. 连问三层"为什么"。
2. 做一个跨领域同构（按下面的四步，缺一步不算）。
3. 写出它**不适用**的边界。

### 跨领域同构怎么做

不是"找个看起来像的东西"，而是四步：

1. **先抽象**——把本知识剥成三要素：
   `对象 = ?　操作 = ?　约束 = ?`
2. **再找候选**——另一个领域里有没有"同样三要素"的结构。
3. **逐条映射**——写三行对应，一行都不能空：
   `本领域对象 ↔ 那个领域的 ?`
   `本领域操作 ↔ 那个领域的 ?`
   `本领域约束 ↔ 那个领域的 ?`
4. **必须指出一处断裂**——哪一部分映射不上、为什么。**这一处才是真正的收获**：它同时说明了两个领域的差别，和这个知识的边界。

**这几种不算同构，出现就打回**：

- 只是名字像、现象像（"都像水流""都是循环"）；
- 只能说"很像"，写不出三要素对应；
- 找不到断裂点——通常意味着你没真的映射，只是感觉像。

**找不到同构也是有效结果**：写下"为什么找不到"，这本身就是一条边界。

**在 DSH 里这样说**
- 「追三层：为什么是 X？那又为什么？再往下呢？」
- 「我把 X 抽象成"对象/操作/约束"，你在另一个领域找一个同构，逐条对应，并指出哪一条断掉。」
- 「给出 X 失效的三种情况。」

**出口**：答出至少两层"为什么"，且给出一条**有效同构**（三要素对应 + 一处断裂）；或给出"找不到同构"的具体理由。
**失败信号**：只会重复定义、举不出反例、同构停在"很像" → 回到第 2 阶段。

## 第 4 阶段：应用

**目标**：产出可判定的东西。

**形态**（按第 0 节的知识类型选，不要三种都做）

| 类型 | 做什么 |
|---|---|
| 程序型 | 做题 / 写代码，闭卷限时 |
| 概念型 | 讲给外行（费曼），接受追问 |
| 判断型 | 写决策理由，让一个反对者来驳 |

**步骤**
1. 选形态。
2. 闭卷、限时完成。
3. 记结果：对、错、卡在哪一步。

**在 DSH 里这样说**
- 「基于我刚学的 X，出 1 道 5 分钟能做完的题，先不给答案。」
- 「给我一个 20 行以内的小任务，只能用 X 完成。」
- 「假装你是不懂这个的外行，听我讲完，指出我没讲清的地方。」

**出口**：留下一次可判定的产出记录。
**失败信号**：做不出来 / 讲不下去 → 记下卡点，进纠错。

## 第 5 阶段：纠错

**目标**：把错误变成结构化记录，并回灌到上游。

**定位优先**：**讲解卡壳处优先于做题错误**——它是更早的探针，往往在你还没做错题的时候就暴露了"这是背的"。

**步骤**
1. 归类：概念错 / 边界错 / 步骤错 / 表达错。
2. 只记「错在哪 + 正确路径」，不抄正确答案。
3. 定重测时间（48 小时或 7 天）。
4. 回灌：概念错→回理解；边界错→回扩展；步骤错→回应用。

**在 DSH 里这样说**
- 「我只记得这个错法，帮我归类：是概念、边界还是步骤问题？」
- 「把这条错误改写成一句可验证的检查项。」
- 「48 小时后只考我这一条，出一道。」

**出口**：错误已归类，且有重测日期。
**失败信号**：同一错误第二次出现 → 标 `复发×2`，回第 2 阶段重写。

## 进度控制（硬规则）

1. **按出口条件推进，不按时间**。每个阶段结束时自问："出口条件满足了吗？差哪一条？"
2. **一次只推进一个阶段**，不要一口气跑完五个。
3. **纠错只由第 4 阶段失败触发**；纠错完成后回到第 2 或第 3 阶段，不回第 1（除非材料本身是错的）。
4. 一轮结束的标记有两样：**一次可判定产出 + 一条被记录的错**。缺一样就是没走完。
5. **费曼只用在概念型知识上**。程序型（手算、写代码）用它纯属浪费时间：讲得溜也可能算错。

## 落盘

- 每轮的产出写进 `D:\Deepseek Workspace\09_Obsidian\20_Notes\`，用 `_templates\笔记模板.md` 的三栏（问题 / 我的答案 / 验证方式）。
- 错误按 `obsidian-output-loop` 的规则记在「验证方式」里，复发就标 `复发×2`。
- 写文件前先给 diff，等用户确认。

## 禁止

- 用"知识总结"代替阶段推进——总结是第 1 阶段的原料，不是成果。
- 跳过第 4 阶段直接说"理解了"。
- 一次提问里塞三个阶段的问题。
- 在用户没作答前替他答。
- 把费曼做成朗读：没有追问的讲解不算讲解。
- 把"很像"当同构，或只做映射不找断裂点。
