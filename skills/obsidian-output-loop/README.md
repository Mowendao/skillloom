# obsidian-output-loop

Obsidian 的输出回路：**只在用户明确调用时运行**，负责「考我—评判—改笔记」「对话压缩成手册」「记到 Inbox」三件事。

触发按字面匹配，不做语义猜测；任何写入都先给 diff，等确认再落盘。

## 何时使用

| 用户说 | 做什么 |
|---|---|
| 调用 obsidian-output-loop / 考我 / 抽查 | 出题 → 评判 → 改笔记 |
| 压缩 / 生成手册 | 把一轮对话压缩成会话手册 |
| 记到 inbox / 记个想法 / 存灵感 | 往 `00_Inbox\_想法.md` 追加一行 |

**不触发**：任务刚做完、对话告一段落、隔了很久、觉得该复习了 —— 都不会自行启动。唯一例外是用户说出一条可复用的判断时，可以问「这条要不要记进 Inbox？」，但只问不写，每个会话最多提 3 次。

## 三条回路

### 1 出题 — 评判 — 改笔记

1. 先读 `20_Notes` 里对应的笔记；没有就说「先写一篇再来考」，不凭空出题。
2. 一次只出一道题，题目必须在笔记范围内，出完就停下等作答。
3. 评判分三类：**事实**（可当场查证，笔记不是权威）、**判断**（不判对错，只问依据和边界）、**笔记没写**（列为空缺，不算答错）。
4. 与笔记不一致的一律列成「分歧」，**裁决权在用户**：覆盖，或保留原文并追加一行裁定记录。
5. 裁决后只列要改的那几行（先 diff），确认后才写。

### 2 对话压缩

写 `10_Reference\会话手册\<主题>.md`，每篇 ≤50 行，固定结构：一句话 / 原来以为 → 现在知道 / 三个关键词 / 还没解决。只追加不重写，超过 80 行拆分；「还没解决」写不出来说明这轮没有认知增量，不该写。

### 3 Inbox 捕获

单文件追加（`00_Inbox\_想法.md`），一行一条：`- 11-06 | <原话> | → ?`。箭头只有四种：`→ 问题` / `→ 项目:<名>` / `→ 判断` / `→ 删`。

平时只报数；过期 ≥3 条、总数 ≥10 条、或用户说「看 inbox」时才列全文。满 20 条停止接收。

## 写入分层

| 位置 | 权限 |
|---|---|
| `20_Notes` | 可以改写（先给 diff） |
| `10_Reference` / `会话手册` | 只追加，不改 |
| `00_Inbox` | 只追加、只删 |

## 安装

```powershell
Copy-Item -Recurse .\skills\obsidian-output-loop "$env:DSH_HOME\skills\obsidian-output-loop"
```

> 注意：`SKILL.md` 里写死的库路径是作者本机的位置，装到别的机器前请改成你自己的 Obsidian 库根目录。
