# 资源清单同款去重

把「一堆标题混乱的条目」变成「按作品归组、可据此删除的 xlsx」。

## 何时用

- 用户给出一个收藏夹 / 合集 / 列表页，问哪些是同一款
- 用户已经导出 CSV / 表格，要做去重
- 用户说「同款判定」「挑出重复」「这些是不是同一款」

不适用：纯文本比较（没有结构化字段）、单条内容判断。

## 铁律

1. **先确认真实覆盖面**，再报数。页面自报条数 ≠ 实际能取到的条数，差额要在结论里写明（见 §6）。
2. **宁可标待核，不要硬判**。判错的代价（删错文件）远高于多留一条。
3. **中文译名不能当主键**。同一部作品能有 3 个完全不同的中文名（实例：「极道无赖:横滨按摩店篇」=「情欲古式按摩店」）。主键永远优先日文原名 / 厂商编号。
4. **区分「不同版本」和「不同作品」**。生肉/汉化/AI汉化/官中/步兵、PC/安卓/模拟器，都是同款；系列的第 1 部和第 2 部不是同款。
5. **合集帖单独处理**。合集（1 个帖子含 N 部作品）与其内含作品的单独帖构成「包含关系」，不能按普通重复删除。

## 流程

### 1. 判断能不能直接抓

依次检查：DNS 解析 → TLS → 代理 → 无头浏览器。

```powershell
Resolve-DnsName <域名> -Type A          # 解析到境外无关 IP（Twitter/Dropbox 段）= DNS 污染
Test-NetConnection <域名> -Port 443 -InformationLevel Quiet
```

常见结果与对策：

| 现象 | 原因 | 对策 |
|---|---|---|
| 解析到一堆无关境外 IP，且每次不同 | DNS 污染 | 让用户开代理 |
| TLS 握手失败 `SEC_E_NO_CREDENTIALS` | 沙箱内 schannel 不可用 | 换 curl.exe（仍可能失败），或直接走 §2 |
| 403 + `Just a moment...` | Cloudflare 人机验证 | 只能用用户自己的浏览器 |
| 无头 Chrome 报 `mojo platform_channel Access Denied` | 沙箱禁止命名管道 | 不要反复重试，直接走 §2 |
| 静态页能取到：`r.jina.ai/<URL>` | — | 可读正文，但通常只给首屏 |

**结论**：有 CF 验证时，唯一可靠路径是让用户在自己的浏览器里导出（§2）。第三方转译服务只能拿到缓存首屏，不要据此声称覆盖全量。

### 2. 导出（三条路，按可靠性排序）

**A. 浏览器控制台脚本（首选）** — 见 `scripts/export_list.js`。

用法：用户在目标页 F12 → Console 粘贴 → 自动滚动到底 → 导出 CSV。

要点：
- 必须**先手动通过** CF 验证再粘贴
- 提醒用户**不要切走标签页**（后台标签的定时器被节流）
- 脚本按实体 id 去重，导出文件名带实际条数，方便核对
- 结束时同时打印捕获到的 API 接口表 —— 这是判断「有没有更干净的取数路径」的证据

**B. 站点 API** — 让用户按 F12 → Network → Fetch/XHR 筛选，滚动几屏后执行：

```js
performance.getEntriesByType('resource').map(e => e.name)
  .filter(n => /api|graphql|ajax|list|item/i.test(n)).slice(-40);
```

拿到返回列表 JSON 的接口后，按 `page`/`limit`/`cursor` 直翻。字段最干净，漏判最少。

**C. 现成扩展**（Instant Data Scraper 等）— 零代码但字段识别不稳，作为兜底。

**必须核对**：导出条数 vs 页面自报条数。差额原因见 §6。

### 3. 解析字段

一份「标题 + 卡片文本」的 CSV，能榨出这些字段：

| 字段 | 来源 | 正则/切法 |
|---|---|---|
| 条目 id | URL | `/p/(\d+)` |
| 厂商编号 | 全文 | `(RJ\d{6,8}|RG\d{5,6}|VJ\d{6}|RE\d{6}|d_\d{6})` |
| 日文原名 | 正文 `原名：`；缺失时从标题取含假名的片段 | 见下方陷阱 |
| 社团 | 正文 `社团名：`；其次标题 `[6位日期][社团]` | — |
| 中文名 | 正文 `名字：`/`名称：` | — |
| 版本 | 标题 | `[vV](\d+(?:\.\d+){1,3})` |
| 容量 | 全文 | `(\d+(?:\.\d+)?\s?(?:GB|MB|G|M))` |
| 标签 | 标题开头 `【…/…】` | 按 `/` 或 `\|` 切 |

**取字段的四个陷阱**（都实际踩过）：

1. **切到下一个字段标签就停**。正文里字段是连排的：`社团名 エロエロ天国 名字 催眠洗脑改 原名 催○洗脳改〜完堕ち温泉編〜 分类 RPG制作大师…`。不设边界会把后面全吃进来。
2. **社团名会污染日文名**。`[エロエロ天国]` 里是片假名，会被当成日文片段混进原名，导致同一系列两条相似度从 0.92 掉到 0.80 以下而漏判。取日文片段时要先剥掉开头的 `[...]`/`【...】` 标签块。
3. **同名不同部分**。`催○洗脳改〜完堕ち病院編〜` vs `催○洗脳改〜完堕ち温泉編〜` 相似度 >0.9，但它们是系列里的两部。这类要判「不同作品」，除非标题明示合集包含。
4. **截断**。日文名常在 `―`、`◆`、`【` 处被切掉尾巴，导致误判为不同款。检查方法：看同组候选的日文名是不是互相为前缀/子串。

### 4. 聚类

用并查集，边按可信度从高到低加：

| 优先级 | 规则 | 阈值 |
|---|---|---|
| 1 | 厂商编号完全一致 | 长度 ≥ 6 |
| 2 | 日文原名（归一化后）完全一致 | 长度 ≥ 8 |
| 3 | 中文名完全一致 **且** 社团一致 | 长度 ≥ 9 |
| 4 | 日文名一方包含另一方 | 双方 ≥ 8 |
| 5 | 日文名模糊相似 | ≥ 0.90 |
| 6 | 中文名模糊相似 | ≥ 0.90 |

归一化：小写 → 删噪声词（汉化版/官中/步兵/存档/完整版/PC/安卓…）→ 只保留假名、汉字、字母数字。

模糊匹配不能 O(n²) 全量比。用**三元组阻塞**：对每条的签名做 3-gram 建倒排，只在共享 gram 的条目间比；再按长度差预筛（`|len差| ≤ max(6, 0.35×较长者)`）。791 条约 30 万对，可直接跑；上万条也够用。

阈值经验：**0.90 自动判重，0.80–0.90 只列候选不自动合并**，交人工。

### 5. 人工复核（不可跳过）

脚本跑完只是初稿。逐组看一遍，重点检查：

- **组内是否混入系列的不同部分**（第 1 部 vs 第 2 部）
- **是否漏了包含关系**（合集帖 vs 单品帖）—— 像上面「社团名污染」造成的漏判，只能靠肉眼补
- **版本倒挂**：编号大的未必版本新（有人把旧版重发一遍）
- **Demo 混入正式版**
- **标题严重不符**：同一款的两个中文名毫无交集（最常见的漏判源）

补漏技巧：按 `社团名` 分组看同名不同标题；把相似度 0.78–0.90 的对全列出来人工扫。

### 6. 必须报告的口径

- 页面自报总数 vs 实际导出数。差额的常见来源：
  - **软删除/审核中/私密**：计数是缓存字段，删了不回收 → 计数虚高
  - **重复渲染**：同一 id 渲染多次 → 按 id 去重后变少
  - **广告卡位**：列表里插的推广卡不带实体链接
- 判定方法：在页面 Console 数「卡片链接总数 / 唯一 id 数 / 重复 id 数」，三者对照即可定位是哪一种。

### 7. 产出 xlsx

五个表（结构见 `scripts/make_xlsx.py`）：

1. `重复组汇总` — 一组一行，★ 标建议保留，给判定依据和置信度
2. `重复组明细` — 每条一行，给「保留/候选删除」
3. `全量明细` — 全部条目带组号，重复组着色，可按组号筛选
4. `拿不准与待核` — 逐条写清「为什么拿不准」+「建议怎么核实」
5. `说明` — 数据来源、主键、视为同款的差异、保留规则、已知局限

**保留建议规则**：版本号最高优先 → 同版本取 id 最大（发布更晚）。必须在说明页声明这是默认建议，用户可按「是否汉化/官中」自行调整。

**已知局限必须写进说明页**：哪些条目缺主键、哪些判定只基于列表页文本、合集未展开。

### 8. 收尾

遵循 `workspace-organizer` 规范：`_输入/` 放原始 CSV，`_产出/` 放交付物，命名 `YYYY-MM-DD_<主题>_<描述>_v<N>.xlsx`；写入前跑 `preflight.ps1`，结束前跑 `audit.ps1`。audit 的既有历史违规（根目录说明文件、他人遗留空目录）只需说明，不得擅自删改。

## 复用清单

| 文件 | 作用 |
|---|---|
| `scripts/export_list.js` | 浏览器控制台导出脚本（滚动 + 抓 id + 导出 CSV + 打印 API 表） |
| `scripts/dedupe.py` | 解析字段 + 并查集聚类，产出 `rows.json` / `groups.json` |
| `scripts/make_xlsx.py` | 由两个 json 生成五表 xlsx |

运行方式（在任务的 `tmp/<task-id>/` 下）：

```bash
python scripts/dedupe.py --csv 输入.csv --id-col id --title-col title --text-col card_text --out .
python scripts/make_xlsx.py --rows rows.json --groups groups.json --out 输出.xlsx \
  --source-url "<合集页 URL>" --input-file "<CSV 路径>"
```

跑完把 `groups.json` 里每组打印出来**逐组人工过一遍**，再生成 xlsx。
